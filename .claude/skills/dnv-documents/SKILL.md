# dnv-documents — генерация черновиков из профиля

Заполняешь документы **только** значениями из `user/case-profile.json` по
реестру `knowledge_base/forms/registry.json`. **Ничего не выдумываешь.**

## Предусловие

Требуется заполненный `user/case-profile.json`. Если его нет — **остановись** и
скажи: «Сначала пройдите интервью: запустите `/dnv-intake`». Не генерируй
документы из догадок. (Проверь также `user/pipeline-state.json`:
`steps["dnv-intake"].status == "completed"`. Контракт предусловий и граф —
`user/pipeline-state.schema.md`; твёрдое предусловие `dnv-documents` — только
`dnv-intake`.)

## Шаг 1. Механическая заливка форм (детерминированно)

Запусти:
```
python engine/scripts/fill_forms.py user/case-profile.json knowledge_base/forms/registry.json --out-dir user/drafts --allowed-root user
```
Это создаёт `user/drafts/<форма>.md` (лист заполнения: поле → значение) и
`user/drafts/drafts.json`. Правила, которые гарантирует скрипт:
- значение поля = значение профиля по `profile_key`;
- нет значения → `[ТРЕБУЕТСЯ: <поле>]` (никогда не подставляется догадка);
- значения доменных полей (напр. `sexo`) берутся как есть из профиля —
  корректность проверит `dnv-review` (field-QA).

> Сами официальные формы MI-T/MI-F заполняются человеком на sede по этому листу
> (движок не подаёт). Листы — это «что вписать в каждое поле».

> **Формы не этого этапа скрипт помечает сам.** `EX-17`, `EX-17-familiar` и
> `tasa-790-012` относятся к этапу **после** одобрения и заполняются в
> `/dnv-tie`. В реестре у них стоит `applies_when` (`case.resolution_notified`,
> для семейной — плюс `family.present`), поэтому `fill_forms.py` выводит их со
> строкой `⏸️ не этот этап`, а `field_qa.py` не считает их `[ТРЕБУЕТСЯ]`
> пропусками. **Ничего вручную игнорировать не надо** — и не надо просить об
> этом пользователя. Если такая форма всё же выдала `MISSING`, это сигнал: в
> профиле уже стоит `case.resolution_notified`, то есть кейс перешёл на этап
> `/dnv-tie`.

## Шаг 2. Текстовые документы из шаблонов (memoria, escritos, queja)

Для свободнотекстовых документов используй `templates/`:
- **`templates/memoria.template.md`** — memoria descriptiva, повествовательная
  часть пакета. Формы дают поля, memoria — связный рассказ: основание,
  описание деятельности, подтверждение отношений, доход и его соотношение с
  порогом, связь с Испанией, перечень приложений. Наполняется из
  `user/case-profile.json` **и `user/spec.md`** (юридические утверждения — только
  оттуда и из `knowledge_base/norms/`, не из общих знаний).
  Условный семейный блок (секция 6) включается только при `family.present=true`
  — иначе секцию **удалить**, а не оставлять пустой.
- `templates/spec_renewal.template.md` (если нужен ориентир spec) — обычно
  заполняется `dnv-synthesis`.
- `templates/escrito_*.template.md`, `templates/queja_defensor.template.md` —
  подставь `{{ПЛЕЙСХОЛДЕРЫ}}` из профиля. Плейсхолдеры, которых нет в профиле
  (например `{{REGAGE_SOLICITUD}}` до подачи) — **оставь как `[ТРЕБУЕТСЯ: …]`**,
  не выдумывай REGAGE/expediente.
Пиши результат в `user/drafts/<имя>.md` (frontmatter A4/2.5cm уже в шаблонах).

## Шаг 3. Самопроверка перед передачей в ревью

- Не осталось ли `{{...}}`-плейсхолдеров (должны быть подставлены или помечены
  `[ТРЕБУЕТСЯ]`).
- Все обязательные поля форм либо заполнены, либо явно `[ТРЕБУЕТСЯ]`.
- Никаких значений «от себя»: каждое значение прослеживается к профилю.

## Шаг 4. Обновление состояния

В `user/pipeline-state.json`: `steps["dnv-documents"] = {status:"completed",
last_run:"<сегодня>", output:"user/drafts/"}`.

## Выход

`user/drafts/` с листами форм (`drafts.json` + `.md`) и текстовыми черновиками.
Подскажи следующий шаг: `dnv-review` (field-QA + official).

> Это **черновики**, требующие независимой экспертной/официальной проверки
>. Движок не подаёт и не платит tasa.
