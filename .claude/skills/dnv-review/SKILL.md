# dnv-review — два слоя ревью + независимая ре-деривация

Проверяешь черновики из `user/drafts/` двумя независимыми слоями. Вывод — для
**черновика, требующего экспертной/официальной проверки**.

## Предусловие

Нужны `user/case-profile.json` и `user/drafts/drafts.json`. Нет — останови и
скажи: «Сначала `/dnv-documents`». Проверь `pipeline-state` (`dnv-documents`
completed). Контракт предусловий — `user/pipeline-state.schema.md`.

## Слой 1A. Механический baseline (детерминированный, исчерпывающий)

```
python engine/scripts/field_qa.py user/case-profile.json knowledge_base/forms/registry.json user/drafts/drafts.json --out-dir user/drafts --allowed-root user
```
Гарантии: **вердикт на КАЖДОЕ поле** реестра (count==полей; молчание = бага),
корректность не правдоподобие, контролируемые словари (ловит `sexo=indefinido`),
галлюцинации (профиль пуст, а в черновике значение → WRONG). Отчёт:
`user/drafts/field_qa_report.md`. Ненулевой выход = есть WRONG.

## Слой 1B. Независимая ре-деривация (two-process)

Механический baseline сравнивает строки. Ре-деривация добавляет смысловой слой и
**доказуемо не видит черновик**:

1. Вызови субагента **field-qa-reviewer**, передав в делегирующем сообщении
   **только** содержимое `user/case-profile.json` и `knowledge_base/forms/registry.json`.
   **Путь черновика НЕ передавай.** Он вернёт ожидаемые значения по каждому полю
   (вслепую) + межполевые замечания.
2. Затем в этом (неограниченном) шаге **сам** прочитай `user/drafts/drafts.json`
   и сдиффай ожидаемые значения с фактическими. Расхождение → WRONG/UNCERTAIN.
3. Изоляция проверяема: ожидаемые значения сгенерированы ДО того, как черновик
   попал в контекст диффа. Если field-qa-reviewer запросил черновик — это
   нарушение, переспроси без него.

Сведи baseline (1A) и ре-деривацию (1B): baseline — пол (must-have), ре-деривация
— потолок (ловит правдоподобные).

## Слой 2. Субстантивное ревью «глазами UGE»

Вызови субагента **official-reviewer**: читает `user/spec.md` + `user/drafts/`,
выдаёт субстантивные замечания (основание, порог дохода, закрытие рисков,
полнота, убедительность). Это не юр-вердикт — риски для последующей экспертизы.

## Шаг 3. Сводный отчёт + состояние

Собери единый отчёт `user/drafts/review_summary.md`:
- field-QA: счётчики OK/WRONG/MISSING/UNCERTAIN + список WRONG/MISSING;
- ре-деривация: расхождения и межполевые замечания;
- official: приоритизированные субстантивные замечания.
Обнови `pipeline-state`: `steps["dnv-review"] = {status:"completed", ...}`.

## Выход

`user/drafts/field_qa_report.md` + `user/drafts/review_summary.md`. Явно укажи:
это черновик; перед подачей нужна независимая экспертная/официальная проверка;
движок не подаёт.
