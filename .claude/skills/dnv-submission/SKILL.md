# Подготовка пакета «готов к подаче» — внутренний справочник

Когда пользователь готов к подаче, твоя задача — собрать **пакет «готов к
подаче»** и инструкции по мониторингу/эскалации. **Подаёт человек.**

## 🚫 Необратимые действия — не твои

Движок **НИКОГДА**:
- не подаёт заявление на sede;
- не платит tasa (Modelo 790);
- не регистрирует expediente и **не выдумывает** REGAGE/expediente/номер;
- **не имитирует** факт подачи и не пишет статус «submitted».

Все `{{REGAGE_*}}` / `{{EXPEDIENTE}}` в документах остаются **`[ТРЕБУЕТСЯ: …]`**,
пока **пользователь** не подал лично и не получил настоящий номер. Конечный
артефакт — чеклист + инструкции, не подача.

## Финальный чеклист пакета

Собери `user/drafts/submission_checklist.md` из:
- **реестра** `knowledge_base/forms/registry.md` (формы MI-T/MI-F, tasa);
- **чеклиста документов** spec §3 (`user/spec.md`) — основной заявитель + семья;
- **статусов** из `user/drafts/review_summary.md` (что OK / что WRONG/MISSING).

Если spec или review_summary ещё нет — работай с тем, что есть, и пометь,
что риски/основания не сверены со spec.

По каждому документу: `[ ]` статус, критичность, «где взять/донести». Отметь
`[ТРЕБУЕТСЯ]`-поля из черновиков, которые надо закрыть **до** подачи.

## Арифметика окна подачи (для renovación)

Из профиля (`applicant.tie_expiry`, `applicant.first_approval_date`) и норм
(`knowledge_base/norms/plazos-silencio.md`) посчитай даты:
- **начало окна — ориентир, а не норма:** «≈60 дней до истечения TIE» — это
  **практика**; нормативный якорь в базе **не установлен** (art. 76 числа «60» не
  содержит — оно стоит в art. 74 quáter.3 и относится к переходу visado →
  autorización). Подавай его с пометкой **«(проверить вживую)»**, не как расчётный
  дедлайн;
- **дата истечения TIE** — из профиля, точная;
- **поздний «хвост» — 90 дней после истечения:** это **art. 76.3**, норма. Но
  оговорка нормы обязательна к передаче: подача в хвосте продлевает разрешение, но
  **не защищает от `expediente sancionador`**;
- рекомендуемая дата подачи; оплатить tasa (**790-038**) за 1–2 дня до.
  ⚠️ **При `family.present` бланков два** — `tasa-790-038` и
  `tasa-790-038-familiar`: пошлина платится отдельным бланком на **каждого
  заявителя**, с его именем и его NIE. Проверь, что оплачены оба, иначе человек
  приходит с недоплатой.

**Даты — арифметика из профиля, не выдумка.** Нет `tie_expiry` (initial) —
пропусти окно и отметь: **у первичной подачи окна нет**, ограничитель — законность
пребывания (конец разрешённых 90/180), см. `norms/solicitud-inicial.md` §4.

## Каналы мониторинга (после подачи пользователем)

| Канал | URL | Что смотреть |
|---|---|---|
| Carpeta Ciudadana → Mis Expedientes | carpetaciudadana.gob.es | estado expediente |
| DEHú | dehu.redsara.es | notificaciones (requerimiento + resolución); **срок ответа тикает отсюда** |
| Sede inclusion (consulta) | sede.inclusion.gob.es | консультация по REGAGE |

Напомни: **срок ответа на requerimiento тикает с уведомления в DEHú** — не пропустить.

## Плейбук эскалации (по нарастающей)

Опирается на `knowledge_base/norms/plazos-silencio.md` (art. 76, silencio
positivo) и шаблоны `templates/`. **Заполнять из профиля; REGAGE — только после
подачи пользователя (иначе `[ТРЕБУЕТСЯ]`).**

| Ситуация | Действие | Шаблон |
|---|---|---|
| Приближается истечение TIE, ответа нет | `recordatorio` (мягко) | `templates/escrito_recordatorio.template.md` |
| Срок рассмотрения истёк без requerimiento | запросить сертификат **silencio positivo** | `templates/escrito_silencio_positivo.template.md` |
| Сертификат silencio не выдан в срок (~15 дней) | `agilización` + резерв права на recurso | `templates/escrito_agilizacion.template.md` |
| Длительное бездействие администрации | **queja** в Defensor del Pueblo (portal-sac.defensordelpueblo.es) | `templates/queja_defensor.template.md` |
| Отказ / исчерпаны меры | recurso (de alzada / contencioso) — **к юристу** | (вне v1: экспертная помощь) |

Подставь `{{плейсхолдеры}}` из профиля; неизвестное/до-подачное → `[ТРЕБУЕТСЯ]`.
Пиши заполненные escritos в `user/drafts/`.

> **Silencio positivo — не автоматика:** сроки и точку отсчёта проверить (verify);
> опираться на норму + свежий рисёрч, не только на практику сообществ.

## Форма вывода: чеклист или доска задач

- **По умолчанию — markdown-чеклист** (`user/drafts/submission_checklist.md`),
  ноль настройки. Этого достаточно.
- **Опционально — доска задач.** Спроси пользователя, хочет ли он вести
  подачу/мониторинг на доске. Варианты (в порядке возрастания трения):
  1. **GitHub Issues в ПРИВАТНОМ репо** — через `gh` CLI, который уже есть в
     Claude Code; ставить ничего не надо. Один issue = один пункт чеклиста.
  2. **Trello MCP** (комьюнити-сервер, официального нет): предложи установить
     `claude mcp add trello -- npx -y mcp-server-trello` + API key/token с
     trello.com/power-ups/admin. После подключения создай доску с колонками
     **Собрать → Проверить → Подать → Мониторинг** и карточками из чеклиста.
  3. **Notion MCP** (официальный, mcp.notion.com) — страница-доска с теми же
     колонками/карточками.
- **PII-правило для ЛЮБОЙ облачной доски:** в текстах карточек — **никаких
  profile-derived значений**: ФИО, NIE/паспорт, REGAGE/expediente, адреса,
  телефоны/email, названия работодателей/клиентов/банков, номера
  договоров/счетов, суммы. Только generic-названия задач и даты («Оплатить
  tasa 790-038 до <дата>», «Запросить письмо у заказчика»), детали остаются в
  `user/`. Облачная доска — внешний сервис, туда уходит только то, что можно
  показать постороннему.
- Если MCP-инструмент не подключён — не изобретай его вызовы: дай команду
  установки и продолжи с markdown-чеклистом.

## Выход

`user/drafts/submission_checklist.md` + заполненные (при необходимости) escritos.
Явно: это **пакет для самостоятельной подачи**; движок **не подавал** и не платил
tasa; актуальную процедуру/суммы/формы сверить вживую; при отказе/сложностях —
независимая экспертная/юридическая помощь.
