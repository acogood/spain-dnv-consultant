# dnv-synthesis — единый источник правды (user/spec.md)

Собираешь `user/spec.md` — обезличенный (значения из профиля, не дублируются
наружу) единый источник правды с **тегами достоверности и as-of** по шаблону
`templates/spec_renewal.template.md`.

## Предусловие (KTD12 — см. `user/pipeline-state.schema.md`)

- Твёрдое: `dnv-research` = `completed` (есть `user/research-notes.md`) и есть
  `user/case-profile.json`. Нет — **остановись**: «Сначала `/dnv-research`».
- Мягкое: `dnv-chat-mining`. Если **не** `completed` — работай, но **пометь**,
  что практика взята только из опубликованного дайджеста
  (`knowledge_base/practice/`), без свежих локальных slices (полнота снижена).

## Шаг 1. Собери входы

1. `user/case-profile.json` — значения для `{{ПЛЕЙСХОЛДЕРОВ}}`.
2. `user/research-notes.md` — **живые находки** (с источниками и as-of).
3. `knowledge_base/norms/*` — норм-каркас + **as-of** даты.
4. `knowledge_base/practice/digest.md` — практика (мнение).
5. `templates/spec_renewal.template.md` — структура spec (0–12).

## Шаг 2. Слей в spec

Заполни каждую секцию шаблона:

- **Плейсхолдеры `{{...}}`** — подставь из профиля. Нет значения → оставь
  `[ТРЕБУЕТСЯ: …]`, **не выдумывай** (особенно REGAGE/expediente — их нет до
  подачи; §0 остаётся «не подано»).
- **Каждое утверждение — с тегом** `[норма] | [официальное разъяснение] |
  [практика — консультант] | [практика — Telegram] | [не подтверждено]`.
- **Пороги/процедурное** — бери **живые** значения из `research-notes` (с годом +
  источником); если research-notes дал `[не подтверждено]` —
  сохрани пометку «(проверить вживую)», не подставляй устаревшее из базы как факт.
- **Приоритет источников при конфликте:** живой `[норма]` (BOE) > база `[норма]` >
  `[официальное разъяснение]` > `[практика]`. Расхождения база↔живое фиксируй в
  §11 «Расхождения».
- **Практика** (§4.7, §2 уточнения) — из дайджеста, с явным «Telegram = мнение».

## Шаг 3. Шапка достоверности прохода

В начало `user/spec.md` добавь блок:

```markdown
> **Синтез от:** <дата>  ·  **Рисёрч от:** <дата research-notes>
> **Практика:** <дайджест | дайджест + свежие slices>
> As-of норм-базы: 2026-06 (перепроверено вживую там, где помечено).
```

## Шаг 4. Приватность (KTD13)

Значения профиля идут **только** в `user/spec.md` (gitignored). **Не** дублируй
NIE/имена/суммы/адрес в `CLAUDE.md`, память или любой коммитимый файл.

## Шаг 5. Обнови состояние

`steps["dnv-synthesis"] = {status:"completed", last_run:"<сегодня>",
output:"user/spec.md"}`.

## Выход

`user/spec.md` — все секции 0–12, теги на каждом факте, as-of в шапке,
плейсхолдеры подставлены или `[ТРЕБУЕТСЯ]`. Следующий шаг: `dnv-verify`
(devils-advocate сверит claim'ы). Затем `dnv-documents` (если ещё не сделаны).

> `user/spec.md` — **черновик-ориентир**, не юридическая консультация и не подача
> (R21). Каждый `[не подтверждено]` — в «список внешних проверок» верификации.
