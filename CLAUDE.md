# CLAUDE.md

Guidance for Claude Code working in this repository.

## Что это

Шаблон-репозиторий: персональный консультант (на базе Claude Code) для
**самостоятельной** подачи/продления испанского ВНЖ *teletrabajo de carácter
internacional* (digital nomad, Ley 14/2013). Вы клонируете репозиторий,
открываете его в Claude Code и проходите пайплайн: интервью → рисёрч → синтез →
документы → ревью → пакет «готов к подаче».

> ⚠️ **Это НЕ юридическая консультация.** Вывод движка — **черновик, требующий
> независимой экспертной/официальной проверки**. Движок **никогда не подаёт
> сам**, не платит tasa, не регистрирует expediente — останавливается на пакете
> «готов к подаче». Подробности: `LEGAL_DISCLAIMER.md`.

## Архетип v1

autónomo/контрактор (por cuenta propia), соло или с **cónyuge** как зависимым
членом семьи (`family.present` в профиле; семейная ветка опциональна).
Иные формы занятости (por cuenta ajena) и дети как основные заявители —
**вне v1**: если кейс не подходит, скажите об этом прямо и пометьте «вне v1»,
не подгоняя.

## Рабочий язык

Контент — **русский** с испанскими юридическими терминами inline (cónyuge,
silencio positivo, requerimiento). Сохраняйте эту конвенцию.

## Приватность (КРИТИЧНО)

- **Все персональные данные живут только в `user/`** — рекурсивно gitignored.
  Никогда не выносите значения профиля (имя, NIE, паспорт, доход, адрес,
  REGAGE) за пределы `user/`.
- **НЕ дублируйте значения профиля в этом файле, в памяти или в `*.example`.**
  Субагенты автоматически подгружают `CLAUDE.md` — если поместить сюда NIE/имя,
  «изолированное» ревью их увидит (ломает two-process изоляцию field-QA).
- Практика сообщества републикуется **только** как обезличенный агрегированный
  дайджест (`knowledge_base/practice/`) — без сырых сообщений и имён.

## Структура

- `knowledge_base/` — PII-free база: `sources/primary/` (**дословные тексты** законов
  и Instrucción с BOE — якорь `[норма]`), `norms/` (разбор норм с as-of датами,
  переякоренный на `primary/`), `practice/` (обезличенный дайджест), `sources/`
  (`reports/` — AI-отчёты + отчёт по правоприменению; `youtube-consultant/`,
  `telegram-consultant/` — публичные каналы), `forms/` (реестр полей форм).
  **При расхождении `norms/` и `sources/primary/` прав `primary/`.**
- `templates/` — шаблоны spec/escritos/queja с `{{плейсхолдерами}}`.
- `engine/scripts/` — параметризованный Python на одной стандартной библиотеке
  (chat-анонимайзер, дайджест, extract_claims, заполнение форм и field-QA).
- `.claude/skills/` — `dnv-intake`, `dnv-research`, `dnv-chat-mining`,
  `dnv-synthesis`, `dnv-verify`, `dnv-documents`, `dnv-review`, `dnv-submission`,
  `dnv-status` (снимок «где я», read-only), `dnv-tracking` (ведение **до**
  резолюции, повторяемый), `dnv-tie` (последняя миля **после** резолюции:
  huellas, EX-17, tasa 790-012, recogida, regreso; повторяемый).
- `.claude/agents/` — `devils-advocate`, `field-qa-reviewer`, `official-reviewer`.
- `user/` — **GITIGNORED** рабочее пространство (профиль, документы, выгрузки,
  черновики, `pipeline-state.json`).
- `example/` — синтетический сквозной пример (фиктивные значения).

## Как работать

1. **Начните с `/dnv-intake`** — собирает профиль кейса в
   `user/case-profile.json` (единый источник правды) и инициализирует
   `user/pipeline-state.json`.
2. **Роутер первого сообщения.** Пользователь описывает кейс или задаёт вопрос,
   не вызывая навык → нет `user/pipeline-state.json` — предложите
   `/dnv-intake` («интервью соберёт профиль, дальше поведут навыки»); файл
   есть — предложите `/dnv-status` («покажет, что сделано и какой шаг
   следующий»). Одной строкой, без лекции.
3. **Порядок навыков — конвенция, не жёсткая последовательность.** Каждый навык
   на входе читает `user/pipeline-state.json` и **проверяет предусловия**: если
   их нет — останавливается с инструкцией, а не догадывается.
   Рекомендуемый поток: intake → research → (chat-mining) → synthesis → verify →
   documents → review → submission → tracking → **tie** (после резолюции).
   `/dnv-status` — в любой момент.
4. **Каждый факт несёт тег достоверности** (`[норма]`, `[официальное
   разъяснение]`, `[практика — консультант]`, `[практика — Telegram]`,
   `[не подтверждено]`) и, для процедурного/порогового, **as-of дату**.
   «Telegram = мнение, не закон» — нельзя апгрейдить практику до нормы.
   **Тег `[норма]` проверяем:** утверждение, которое не подтверждается дословным
   текстом в `knowledge_base/sources/primary/`, этот тег нести не может.
5. **Ad-hoc вопросы после synthesis.** Если `user/spec.md` уже собран,
   отвечайте на вопросы по кейсу, опираясь на него, с теми же тегами
   достоверности; чат-ответ не выдавать за проверенный факт — спорное →
   «(проверить вживую)» / `/dnv-verify`.
6. **Документы заполняются строго из профиля** через реестр полей
   (`knowledge_base/forms/`). Поля без данных → `[ТРЕБУЕТСЯ: …]`, не выдумка.
7. **Датированность.** Базе нужна сверка вживую, но **не всей**: что написано в
   законе — лежит дословно в `sources/primary/` и сверки не требует; **суммы и
   текущие процедуры** (SMI, эпиграфы/суммы tasa, состав пакета, бланки, реальные
   сроки) — требуют, и помечены «(проверить вживую)». Устаревшее → архивировать.
   Апдейты базы не гарантируются.

## first-run

Если навыки `/dnv-*` не видны после клонирования — перезапустите сессию Claude Code
один раз (skills/agents подхватываются при открытии папки). MCP-интеграции
(Trello / Notion — для опциональной доски задач в `dnv-submission`) не
обязательны: без них движок полностью функционален.
