# MVP-гейт (U19) — критерии и решение

Ранний валидационный гейт (R24/KTD): проверить премису движка на **тонком
срезе** ПРЕЖДЕ чем строить дорогие слои (research / chat-mining / synthesis /
submission / расширения). Если премиса проваливается — пересмотр до вложения в
остальное.

## Премиса под проверкой

> Технически-комфортный незнакомец, открыв форк, безопасно получает **корректный
> черновик**: профиль собирается без пробелов, документы заполняются строго из
> профиля (без галлюцинаций), а механическое ревью ловит ошибки — включая
> правдоподобные-но-неверные.

## Тонкий срез

`intake → draft → field-QA` на синтетическом кейсе `example/mvp-case/`,
**прогон выполняет не-автор** (свежий контекст, по докам, без знания реализации).

## Критерии прохождения

1. **Профиль без пробелов.** На синтетике все обязательные поля активной ветки
   заполнены; пробелы видны как `[ТРЕБУЕТСЯ]`, не как выдумка.
2. **Черновик строго из профиля.** Каждое значение поля прослеживается к
   профилю; отсутствующие → `[ТРЕБУЕТСЯ: …]`.
3. **Field-QA исчерпывающ.** Вердикт на 100% полей реестра (count==полей).
4. **Ловит посаженный баг.** Грубый (вне домена) И правдоподобный (mismatch /
   галлюцинация) → WRONG.
5. **Воспроизводимо не-автором** за разумное время по `example/mvp-case/README.md`
   без знания внутренней реализации.

## Гейт

Пока гейт **не пройден** — НЕ строить U8 (research/synthesis), U9
(chat-mining/verify), U12 (submission) и расширения архетипов. (Анонимайзер U2,

Альтернатива при провале: **content-first pivot** (KB + чеклисты + реестр +
пример как референс-репо; движок — второй фазой), см. Open Questions плана.
